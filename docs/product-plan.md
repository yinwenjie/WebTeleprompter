# WebTeleprompter 产品规划

> 一款纯前端、免安装的网页提词器，面向直播与录播创作者。基础功能（输入文本、设定语速、滚动显示）之上，本文定义上线必备的 P0 功能集、取舍依据、MVP 范围与迭代路线。

## 1. 产品定位与目标用户

**定位**：打开浏览器即用、零学习成本、可靠不掉链子的提词工具。不做内容创作平台，不做账号体系，专注"把稿子以合适的速度、合适的样式呈现在镜头旁边"。

| 用户群 | 典型场景 | 核心痛点 |
| --- | --- | --- |
| 直播主播（带货、游戏、知识直播） | 开播时第二屏/平板放提词，边看边讲 | 长时间直播稿件长，需随时暂停、跳段；灯光下屏幕反光，需高对比度 |
| 短视频 / 录播创作者 | 手机或电脑摄像头前录口播，一遍过 | 语速与稿件节奏不匹配，频繁 NG；需靠近镜头读避免眼神漂移 |
| 企业宣讲 / 培训 / 远程会议 | 线上路演、课程录制、视频会议发言 | 临时需要，不想装软件；需要稿件随手保存、多份切换 |
| 使用反射式提词器硬件的用户 | 相机 + 分光镜 + 平板 | 必须镜像显示，且能远程控制，不能碰屏幕 |

共同诉求：**上手快、不卡顿、显示清晰、控制顺手、稿子不丢**。

## 2. 竞品 / 参考分析

| 产品 | 形态 | 亮点 | 不足 / 可借鉴教训 |
| --- | --- | --- | --- |
| Teleprompter.com | 网页 + App | 语音跟读（Voice Scroll）、远程控制、云同步 | 高级功能付费；免费版带水印与功能限制 |
| CuePrompter | 纯网页 | 极简，设置即用，速度/字号/镜像/配色齐全 | UI 陈旧、无稿件保存、无移动端适配 |
| Teleprompter Premium（iOS） | 移动 App | 蓝牙遥控、镜像、倒计时、丰富排版 | 仅 iOS，需购买 |
| 提词全能王 / 提词器大师 | 移动 App | 悬浮窗提词、语音识别跟读、字幕导出 | 会员制、广告多；悬浮窗依赖系统权限 |
| OBS 提词插件 / 浏览器源 | 桌面插件 | 与推流软件集成 | 配置门槛高，非通用 |

**共性功能（行业基线）**：速度调节、字号 / 颜色 / 背景、镜像翻转、全屏、播放暂停与快捷键、阅读参考线、倒计时。**差异点**：语音跟读（智能跟随）、远程 / 蓝牙遥控、稿件云同步、悬浮窗。

**对本产品的启示**：行业基线必须全部覆盖（这就是 P0 的主体）；差异化功能（语音跟读、远程控制）技术风险高，放 P1/P2；以"免费、无水印、纯网页、数据留在本地"为核心卖点。

## 3. 基础功能细化

### 3.1 文本输入
- 编辑区为大号 `textarea`，支持粘贴纯文本，自动保留换行与空行（空行视为段落分隔）。
- 显示容量：单稿建议 ≤ 5 万字符，超出给出提示而不是截断。
- 编辑与提词为两种模式，一键切换；提词模式下文本只读，避免误触。
- 字数、预估阅读时长（按当前语速估算）实时显示在编辑区底部。

### 3.2 语速设定
- 内部单位为 **像素/秒**，对用户以 1–10 档（可 0.5 步进）呈现，默认 3 档 ≈ 中文口播 180–220 字/分钟。
- 支持滑杆、`+/-` 按钮、键盘上下键三种调整方式；播放中可实时调整，不中断滚动。
- 语速与字号解耦：字号变化时自动换算，保证"每分钟读多少字"的体感稳定。

### 3.3 滚动显示
- 使用 `requestAnimationFrame` 驱动的平滑滚动，而非 `setInterval`，保证 60fps 且在后台标签页恢复后不"跳跃"。
- 文本自顶部进入前留出一屏空白，首行从阅读线位置开始；末尾同样留出一屏，避免最后一句被截断。
- 滚动到末尾自动停止并显示"已结束"，不自动循环（循环作为可选项放 P1）。

## 4. P0 功能清单

取舍原则：**(a) 行业基线、用户默认期待；(b) 缺了会直接导致"用不了 / 不敢用"；(c) 纯前端可实现、无显著技术风险。** 同时满足者进 P0。

| # | 功能 | 一句话说明 |
| --- | --- | --- |
| P0-1 | 播放控制与快捷键 | 空格暂停/继续，上下键调速，Home 回顶 |
| P0-2 | 外观设置 | 字号、行距、字体、前景/背景配色、边距 |
| P0-3 | 镜像翻转 | 水平 / 垂直镜像，适配反射式硬件 |
| P0-4 | 全屏与纯净模式 | 隐藏一切 UI，仅剩文本 |
| P0-5 | 阅读引导线 / 焦点区域 | 标记当前应读位置 |
| P0-6 | 倒计时与进度指示 | 开始前 3 秒倒计时，播放中显示进度与剩余时间 |
| P0-7 | 稿件本地持久化与多稿管理 | 自动保存、多稿件列表、导入导出 |
| P0-8 | 手动滚动 / 拖拽定位 | 暂停时滚轮、拖动、触摸直接定位 |
| P0-9 | 响应式与移动端适配 | 手机 / 平板可作为独立提词屏 |

### P0-1 播放控制与快捷键
- **描述**：开始 / 暂停 / 继续、加速 / 减速、回到顶部、跳到上 / 下一段。全部有屏幕按钮和键盘快捷键（空格、↑↓、Home、PageUp/PageDown）。
- **为什么 P0**：提词过程中用户双手可能不在鼠标上，没有快捷键等于不可用；所有竞品均具备。
- **核心交互**：按钮悬浮在底部，几秒无操作自动隐藏；快捷键在全屏下仍有效；暂停时在阅读线处显示"已暂停"轻提示。
- **技术点 / 风险**：全局 `keydown` 监听需在编辑态屏蔽，防止输入空格误触发；需防止浏览器默认行为（空格滚屏）。

### P0-2 外观设置（字号 / 行距 / 字体 / 配色 / 边距）
- **描述**：字号 24–120px，行距 1.2–2.0，左右边距可调，字体提供系统无衬线 / 衬线 / 等宽三类，预设配色（黑底白字、黑底黄字、白底黑字）+ 自定义颜色。
- **为什么 P0**：不同距离、不同屏幕、不同灯光下可读性差异巨大；黄字黑底是提词行业的事实标准。
- **核心交互**：设置面板为侧边抽屉，调整即时预览；提供"恢复默认"。
- **技术点 / 风险**：设置持久化到 `localStorage`；字号变化时按 3.2 规则换算滚动速度。

### P0-3 镜像翻转
- **描述**：水平镜像（分光镜提词器必需）、垂直镜像、两者组合。
- **为什么 P0**：使用硬件提词器的用户没有镜像就完全无法使用，是"用不了"级别的需求；实现成本极低。
- **核心交互**：设置面板开关 + 快捷键 `M`；镜像只作用于提词显示区，不影响编辑区与控制按钮。
- **技术点 / 风险**：CSS `transform: scaleX(-1)` 即可；注意镜像后阅读线、进度条位置需同步翻转，拖拽方向需反向映射。

### P0-4 全屏与纯净模式
- **描述**：一键进入浏览器全屏；纯净模式下隐藏所有控件、光标、滚动条，仅保留文本（可选保留阅读线与进度条）。
- **为什么 P0**：提词屏必须最大化利用面积，任何 UI 元素都是干扰；也是录屏 / OBS 浏览器源的前提。
- **核心交互**：`F` 进入 / 退出全屏；鼠标移动时短暂显示控件，静止 3 秒自动隐藏；`Esc` 退出。
- **技术点 / 风险**：iOS Safari 不支持 Fullscreen API，需降级为"页面内全屏"（固定定位铺满视口 + 引导添加到主屏幕）；需处理 `fullscreenchange` 事件同步状态。

### P0-5 阅读引导线 / 焦点区域
- **描述**：在屏幕某一高度（默认 1/3 处，可调）显示一条半透明横线或高亮带，标记"当前应读行"；可选上下遮罩渐隐。
- **为什么 P0**：没有参考线用户眼睛会在屏幕上寻找位置，导致眼神漂移；靠近摄像头的位置（屏幕上部）是最佳读稿区域。
- **核心交互**：位置、透明度、样式（线 / 带 / 遮罩）可在设置中调整；滚动与段落跳转均以该线为锚点。
- **技术点 / 风险**：纯 CSS 覆盖层，`pointer-events: none`；焦点区域位置需作为"当前位置"的统一基准，供进度计算与跳段逻辑复用。

### P0-6 倒计时与进度指示
- **描述**：按开始后 3 秒倒计时（可设 0–10 秒）再滚动；播放中显示进度条、已用 / 剩余时间（按当前速度估算）。
- **为什么 P0**：录播场景需要按下开始后回到镜头前的缓冲时间；直播场景需要掌握剩余时长控制节奏。
- **核心交互**：倒计时以大号数字覆盖在屏幕中央；进度条贴屏幕边缘，纯净模式下可保留为 2px 细线。
- **技术点 / 风险**：剩余时间 = (总高度 − 当前位置) / 当前速度，速度变化时实时重算；实现简单，风险低。

### P0-7 稿件本地持久化与多稿管理
- **描述**：编辑内容自动保存（防抖 500ms）；稿件列表支持新建、重命名、删除、切换；支持导入 `.txt`、导出 `.txt`；记住每份稿件的上次播放位置。
- **为什么 P0**：误刷新丢稿是提词工具最致命的体验事故；主播通常有多份固定话术需要切换；"数据留在本地"也是相对竞品的隐私卖点。
- **核心交互**：顶部稿件下拉 / 侧边列表；删除需二次确认；首次打开预置一份示例稿。
- **技术点 / 风险**：`localStorage` 容量约 5MB，建议稿件数据使用 IndexedDB（可通过轻量封装库）；需做好容量超限提示与 JSON 导出备份路径。

### P0-8 手动滚动 / 拖拽定位
- **描述**：暂停状态下可用鼠标滚轮、拖动滚动条、触摸滑动直接定位；播放中滚轮操作视为"临时微调"并继续播放。
- **为什么 P0**：讲错、跳过、被打断后需要快速回到某处，没有手动定位只能回顶重来。
- **核心交互**：拖动时阅读线保持固定，文本随手移动；松手后 300ms 恢复自动滚动（若之前在播放）。
- **技术点 / 风险**：需统一自动滚动与手动滚动对同一 `scrollTop` 的写入，避免互相覆盖造成抖动；触摸设备需处理惯性滚动与 `touch-action`。

### P0-9 响应式与移动端适配
- **描述**：手机、平板、桌面三档布局；手机横竖屏均可用；提词时阻止屏幕休眠。
- **为什么 P0**：大量创作者直接用手机 / 平板当提词屏（放在相机旁或贴近前置摄像头）；移动端不可用等于失去一半用户。
- **核心交互**：移动端编辑区与提词区切换为全屏单页；控制按钮改为大尺寸触控目标；双击屏幕暂停 / 继续。
- **技术点 / 风险**：Screen Wake Lock API 在部分浏览器需 HTTPS 与用户手势触发；iOS 兼容性是主要风险，需真机测试。

### 放入 P1 / P2 的功能及理由

| 功能 | 优先级 | 理由 |
| --- | --- | --- |
| 远程控制（手机扫码控制电脑） | P1 | 硬件提词器用户强需求，但需 WebRTC / 信令服务或 WebSocket 中继，突破"纯前端"边界；可先用 BroadcastChannel 实现同设备多窗口联动过渡 |
| 文本格式化（高亮、停顿标记、加粗） | P1 | 有价值但不阻塞使用；需引入轻量 Markdown 子集或富文本，增加编辑复杂度 |
| 循环播放、段落自动停顿 | P1 | 小众场景，实现简单，随 P1 一起上 |
| 语音跟读（按语音识别自动跟随） | P2 | 差异化杀手功能，但 Web Speech API 准确率与浏览器支持不稳定，中文效果需验证 |
| 云同步 / 账号 | P2 | 引入后端与隐私合规成本，与"本地优先"定位冲突，视需求再定 |
| 悬浮窗 / 画中画提词 | P2 | Document Picture-in-Picture API 仅 Chromium 支持，待生态成熟 |
| 蓝牙 / 脚踏板遥控 | P2 | 可借助键盘事件映射部分支持，专门适配放后 |

## 5. MVP 范围与迭代路线

| 阶段 | 范围 | 验收标准 |
| --- | --- | --- |
| **MVP（P0）** | 基础三项 + P0-1 ~ P0-9 | 桌面 Chrome / Safari / Firefox 与 iOS / Android 主流浏览器可完整走通"输入 → 设置 → 全屏提词 → 保存"流程；滚动稳定 60fps；刷新不丢稿 |
| **P1** | 远程控制（扫码）、文本格式化、循环与段落停顿、OBS 浏览器源模式（透明背景） | 手机扫码后可控制电脑端播放 / 暂停 / 调速，延迟 < 300ms |
| **P2** | 语音跟读、画中画、云同步（可选）、PWA 离线安装 | 中文语音跟随准确率可接受，离线可用 |

### 技术建议

- **纯前端、静态托管**：MVP 无需后端，可直接部署到 GitHub Pages / Vercel / Cloudflare Pages，零运维成本，天然满足"数据留在本地"。
- **技术栈**：Vite + TypeScript + React（或 Vue 3），理由：状态（设置、稿件、播放状态）较多但不复杂，组件化框架足够且生态成熟；Vite 构建快、产物小。若追求极致轻量，Svelte 亦可。
- **状态与存储**：全局状态用轻量方案（如 Zustand / Pinia）；稿件数据走 IndexedDB（可用 `idb` 封装），设置走 `localStorage`。
- **滚动引擎**：独立为无 UI 依赖的模块，基于 `requestAnimationFrame` 与时间增量计算位移，便于单元测试与后续远程控制、语音跟读复用。
- **样式**：CSS 变量承载主题（颜色、字号、行距），镜像与纯净模式通过根节点 class 切换。
- **P1 远程控制**：优先考虑 WebRTC DataChannel + 极简信令（可用免费托管的 WebSocket 服务或 Serverless 函数），仍保持主应用静态化。
- **质量保障**：滚动引擎与存储层写单元测试；在 iOS Safari 真机上验证全屏降级、Wake Lock、触摸滚动三项高风险点。

## 6. 成功指标

| 指标 | 目标（上线后 1–2 个版本内） |
| --- | --- |
| 首次打开到开始提词的用时 | 中位数 < 60 秒 |
| 单次提词会话完成率（滚动到末尾或主动结束） | > 70% |
| 7 日回访率 | > 25% |
| 移动端访问占比 | > 40%（验证多设备定位） |
| 因丢稿 / 卡顿产生的反馈 | 趋近于 0 |
