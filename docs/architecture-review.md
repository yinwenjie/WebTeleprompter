## 3. 决议

### 3.1 照原文实现会出 bug

**D-01 恢复播放位置的时序有误（架构 §6.1）。** 原文先发 `seek.px`、后发 `mode.set prompt`，但 §4.4 规定编辑态丢弃除 `mode.set` 外的全部命令，所以恢复位置的命令一定被丢掉。此外舞台在编辑态没有挂载，也量不出内容高度。

决议：顺序改为 `mode.set prompt` → 舞台挂载 → 测量并 `reportMetrics` → 发 `seek.progress`。

**D-02 语速公式过不了验收 8-6（架构 §6.2、Q2）。** 原公式按平均字宽估算每行字数，得到 `px/s ∝ fontSize²`。这只在长段落连续换行时成立。口播稿常是一句一行：字号翻倍时不换行，内容高度只变为 2 倍，速度却变为 4 倍，全文时长减半，远超 8-6 允许的 5%。

| 字号 40 → 80             | 内容高度 | 原公式速度 | 全文时长 |
| ------------------------ | -------- | ---------- | -------- |
| 长段落（连续换行）       | ×4       | ×4         | 不变     |
| 短句（每句一行，不换行） | ×2       | ×4         | **减半** |

决议：由实测内容高度反推，不估算字宽。`px/s = 内容高度 ÷ 总阅读秒数`，其中总阅读秒数只取决于阅读单位数和档位。这样全文时长与排版完全无关，还省掉了 Q2 的字宽权重。

已接受的局限：速度按全文平均，行密度差异大的稿件局部节奏会有偏差。若用户反馈明显，可以在引擎内改为分段速度，接口不变。

**D-03 切换全屏后阅读位置会跳（架构 §6.4、验收 8-3）。** 原文要求“位置 px 不变”。但进入全屏常常改变宽度，文字重新换行后内容高度随之变化，px 不变意味着阅读线下换成了另一段文字。

决议：`setMetrics` 在内容高度变化时按比例缩放位置以保持 `progress`；只有视口高度变化时位置不变。验收 8-3 改为比较 `progress`。

**D-07 编辑态按键会失效（架构 §4.1、§6.2）。** `CommandBus.dispatch` 返回 `void`，`KeyboardInput` 不知道命令是否被丢弃。如果一律 `preventDefault`，编辑区就打不了空格、移不了光标；如果都不阻止，提词时空格会滚动页面（8-7 要求不能）。

决议：`dispatch` 返回 `boolean`，`KeyboardInput` 只在返回 `true` 时阻止默认行为。另外，焦点在输入控件上时直接不处理，焦点在按钮上时不拦截空格。同时补上原文缺失的命令：`display.toggleClean`、`display.exitFullscreen`（fallback 全屏需要自己响应 `Esc`）、`display.toggleHelp`。

**D-09 `pagehide` 时写 IndexedDB 不可靠（架构 §4.4、§6.5）。** 异步事务在页面卸载时不保证完成，而验收 8-5 要求进度恢复。

决议：新增同步暂存键 `wtp.progress.<id>`，`pagehide` 时写入，下次启动时合并到稿件。另外规定保存播放位置不得改动 `updatedAt`，否则播一下稿件库的排序就变了。

**D-10 状态机有未定义路径（架构 §4.4）。** 补全如下，完整转换表见 [core-playback.md](./dev/modules/core-playback.md)：

- `ended` 时按播放：原文没有出边，空格会失效。决议为从头开始。
- `idle` / `ended` 时拖拽：原文只有 `playing` / `paused` 能进 `scrubbing`，但打开稿件后先拖到某处是常见操作。决议为松手后进入 `paused`。
- `countdown` 时拖拽：取消倒计时，松手后进入 `paused`。
- 恢复等待的 300ms 内再次按下：取消恢复。
- 空稿件时按播放：停留在 `idle`，不启动。
- 切换稿件：新增 `controller.resetSession()`。

**D-11 去掉 `content-visibility: auto`（架构 §7.1）。** 它让屏幕外段落跳过布局，因此实测的内容高度和段落偏移都不准，滚动时占位尺寸还会被真实尺寸替换，导致高度跳变和 `ResizeObserver` 反复触发，同时破坏滚动路径“零 layout”的目标。Safari 18 才支持，也覆盖不了 iOS 目标。

决议：P0 不用。长文本性能交给 8-4 的实测（见 R-2）。

**D-18 编辑态的语速滑杆会失效（架构 §4.4）。** 设置面板可以在编辑态打开，但语速必须走命令（D-08），而编辑态命令全被丢弃。

决议：编辑态拦截器放行 `mode.set` 和 `speed.set`。键盘只产生 `speed.step`，所以按键不会穿透。

### 3.2 违反文档自身的依赖规则

**D-04 跨层调用改为端口和桥接。** 原文时序图多处与 R1–R3 及 §4.3 冲突：

| 原文                                                      | 违反                     | 决议                                            |
| --------------------------------------------------------- | ------------------------ | ----------------------------------------------- |
| `Ctl → settingsStore`、`Ctl → displayStore`（§6.2、§6.4） | R1                       | `PlaybackEffects` 端口，由 bootstrap 接到 store |
| `UI → Engine.setMetrics`（§6.1、§6.4）                    | R3                       | `StageBridge`，实现放在 bootstrap               |
| `settingsStore → engine.setSpeed`（§4.2）                 | “仅 Controller 调用引擎” | `controller.updateLayout()`                     |
| `FullscreenAdapter → displayStore`（§4.2）                | R2                       | 适配器提供 `onChange`，由 bootstrap 接线        |
| `RemoteTransport` 订阅 `playbackStore`（§3.5）            | R2                       | 由 bootstrap 接线                               |

**D-05 新增 `core/ports/`。** R1 和 R2 要求 platform 实现 core 定义的接口，但原文把仓储等接口列在 platform 下，core 也没有定时能力（倒计时和拖拽恢复都需要）。决议：仓储、显示、文件、时钟的接口全部放到 `core/ports/`。

**D-06 引擎不再自行响应页面隐藏（架构 §4.4 与 §7.1 冲突）。** 一处说转为 `paused`，另一处说引擎自动 `stop`，后者会造成 `phase` 仍为 `playing` 而引擎已停。决议：新增 `PageLifecycle` 适配器，隐藏时发 `pause` 命令（source `system`）。dt 截断移到引擎内：`FrameScheduler` 只提供绝对时间，dt 本来就在引擎里计算，这样也能用 `FakeFrameScheduler` 测试 8-11。

**D-08 明确重复状态的所有者。**

| 状态         | 原文的矛盾                                                                                             | 决议                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 镜像         | `Settings.display.mirrorX` 持久化，§6.4 却让 `displayStore` 切换，而 §3.2 的 `displayStore` 并不拥有它 | 归 `settingsStore`，`display.toggleMirror` 路由过去                              |
| `speedLevel` | §4.2 说归 Controller，`Settings.playback` 也有一份                                                     | 运行时真值在 Controller，settings 只是持久化副本。滑杆发 `speed.set`，不写 store |

**D-14 不用 zod。** §5.3 允许 zod，但 §1.1 要求 core 只依赖标准库，而且它要占首屏包体。决议：手写校验。

**D-20 i18n 移出 app。** §3.4 放在 `app/i18n`，但 ui 要调用 `t()`，这形成 ui → app 的反向依赖。决议：放到叶子层 `src/i18n/`。

### 3.3 接口和模块的补全

**D-12 “命令必须幂等”不成立（架构 §4.3）。** `toggle`、`speed.step`、`nudge.px` 本质上不幂等。决议：改为“同步执行；在当前阶段无效的命令是空操作，绝不抛错”。P1 远程控制若要重传，需要另加序列号去重。

**D-13 接口补全。**

- `setMetrics` 接收 `paragraphOffsetsPx`（架构 Q3 的结论，但 §4.1 的接口没有写）。
- 新增 `engine.setTarget()`，因为舞台会反复挂载和卸载。
- 新增 `seek.progress` 命令，用于恢复位置和点击进度条，调用方无需知道内容高度。

**D-15 明确 `ScrollState` 推送频率。** §6.1 写 4Hz，§7.1 写 4–10Hz，都没说节流放在哪。决议：引擎内部节流到 10Hz，状态变化（含 `atEnd`）立即推送；每帧只调用 `target.apply`，不分配对象，避免 GC 抖动。

**D-16 段落规则。** 规划说空行分段，架构注释说 `\n` 分段。决议：以空行分段；全文没有空行时，每个非空行算一段，否则按 PageDown 会直接跳到文末。

**D-17 手势细节（架构 §6.3）。**

- 原文 `pointerdown` 就发 `scrub.begin`，会让每次点击和双击都打断播放。决议：移动超过 8px 才算拖拽。
- 原文的惯性 `nudge` 和 `scrub.end` 同时发出，惯性还没走完就恢复播放了。决议：惯性结束后才发 `scrub.end`。

**D-19 草稿暂存节流（架构 §6.5）。** 每次按键同步写 localStorage，5 万字时约 100KB，移动端输入可能掉帧。决议：节流到 100ms，`pagehide` 时同步写出。刷新和关闭都不丢稿，只有进程在 100ms 窗口内崩溃才可能丢这一点内容。

**D-21 补上漏掉的适配器。** 架构要求的行为没有对应模块，违反“DOM 事件只在 platform 内监听”：`PageLifecycle`（页面隐藏）、`ViewportMonitor`（`viewportClass`）、`ActivityMonitor`（控件自动隐藏）。另外规划 P0-6 的“已用时间”在 `ScrollState` 中没有字段，决议由 `positionPx / speed` 派生，与“按当前速度估算”一致。

### 3.4 工具链版本

**D-22 工具链升级到当前大版本（原 Q-A，已确认升级）。** 架构 §2 指定的版本已落后，升级前开发依赖有 12 个漏洞（含 2 个 critical）。升级在开工前完成，没有迁移成本。

| 工具                        | 架构原文               | 现在                         | 说明                                                                                          |
| --------------------------- | ---------------------- | ---------------------------- | --------------------------------------------------------------------------------------------- |
| Vite                        | 5                      | 8                            | 打包器换成 Rolldown。已确认 `safari15` 目标仍然生效                                           |
| Vitest                      | —                      | 5                            |                                                                                               |
| ESLint                      | —                      | 10                           |                                                                                               |
| `eslint-plugin-react-hooks` | —                      | 7                            |                                                                                               |
| TypeScript                  | 5                      | **6.0**（不是最新的 7）      | `typescript-eslint` 只支持 6.1 以下，因此用 `~6.0.3` 锁定。等它支持 TS 7 后再升               |
| 依赖规则插件                | `eslint-plugin-import` | **`eslint-plugin-import-x`** | 原插件不支持 ESLint 10，且 2025 年 6 月后没有发布。规则相同，`lint:arch` 的 23 条样例全部通过 |
| React                       | 18                     | 18（不变）                   | 不属于工具链。§2 的选型理由是否适用于 19，单独评估                                            |

Node 要求随之提高到 22.22+ 或 24.15+（Vitest 5、jsdom 31）。

升级后的 `npm audit`：生产依赖 0 个漏洞。开发依赖还有 11 条 moderate，都来自 lint 工具依赖的 `minimatch`（glob 模式导致的 DoS）。它只在 lint 时运行，模式都来自我们自己的配置，不接触不可信输入，也不进入部署产物。npm 建议的“修复”是把 ESLint 降回 9，因此不采用，等上游更新。
